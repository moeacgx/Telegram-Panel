# wgcf 共享运行器合同

适用于 v1.31.82 的内置运行器和独立 `tools/wgcf-warp`；部署和成功判据见
[运维步骤](../deployment/wgcf-wireproxy.md)。本版将轻量出口并入统一代理列表并移除旧 Docker
WARP 运行管理。沿用 v1.31.81 的受管出口标识，模块 ABI 不变；升级和回滚约束见下文。

## 生命周期与安全边界

- `warpctl.py` 只依赖 Python 3.11+ 标准库。Linux 容器为生产运行目标，Windows 仅运行
  不涉及 POSIX 子进程信号的测试。所有上游 CLI 使用参数数组启动，禁用 shell 和标准输入。
- `register` 仅在显式 `--accept-tos` 时发起注册。首次调用先持久化尝试标志；中断后存在完整
  TOML 则复用，否则进入人工核对状态。每 profile 独立 CLI 进程，不把 wgcf 的全局认证客户端
  当成多账户 SDK。上游进程单次最多 45 秒，超时杀死并回收子进程。
- `generate` 只接受 Interface/Peer 白名单字段，要求注册私钥一致和 IPv4/IPv6 全路由，
  使用固定 wireproxy `-n` 检查。禁止配置钩子、WGConfig、TunnelDomains 和环境变量插值。
- 目录 0700，文件 0600，进程 umask 0077；同目录 fsync + replace 原子落盘，拒绝符号链接
  和路径穿越。共享数据卷只允许本工具访问，不视为恶意本机管理员间的隔离边界。
- CLI 操作互斥；supervisor 使用独立进程锁，读取原子元数据，不受注册网络等待阻塞。
  每个 profile 一个 wireproxy 子进程，停止和退出时 terminate/wait/kill；异常退出冷却 30 秒。
  单份元数据损坏或进程无法创建只标记该档案 `failed`，不终止其它正常出口。
  每次启停写入随机修订号，运行器执行后回写同一修订号；曾启动的档案只有最新停止请求
  被确认且状态为 `stopped` 才能重新生成，防止异步 stop/generate/start 保留旧密码进程。
  进程日志不持久化，不把配置、Token、Cookie、私钥或上游错误文本转发到 API/终端。
- 用户态 WireGuard 只在进程内部处理流量。共享容器不持有 NET_ADMIN、TUN 或 Docker
  Socket，不建立宿主接口；共享容器故障会影响其全部出口，不能宣称进程级高可用。

## 面板内置运行器

`WgcfWarpService` 仅在 Linux 主容器中启用，使用发布目录内的 `warpctl.py` 与镜像固定的
wgcf 2.3.0、wireproxy 1.1.3。它以 `/data/wgcf-warp`（或配置的持久根）保存材料，在
子进程退出时以 TERM、超时、进程树清理的顺序结束监督器。依赖缺失会使专用 API 返回不可用，
不能阻塞面板启动。

`POST /api/panel/proxies/wgcf` 必须提供 UUID 请求标识、名称和条款接受标志，返回已持久化的
档案状态；同一
标识对应 `web-<uuid>`，后台 `provision` 只会注册、生成并开始期望运行一次。`GET` 返回白名单
状态，绝不返回 Token、私钥、密码、配置或上游输出。`start`、`stop`、`test`、`resume` 也是
专用端点。创建、检测和启停可超过常规 API 时限，因此页面只轮询状态，不以 HTTP 连接存活
作为完成判据。

已有修订号的档案重复执行 `provision` 会保留期望启停状态和注册材料；恢复后台任务会显式
执行 `start`，而不是依赖配置命令隐式启用。网页启停以状态锁、工具锁的固定顺序串行化，
读取和持久化期间保持状态锁，避免并发恢复的 `creating` 被旧启停结果覆盖。

`OutboundProxies.ManagedWgcfProfile` 是唯一、可空的受管标识。常规创建/导入/编辑/删除、全局
代理都会拒绝该标识或同一 loopback 端口。单账号已有代理绑定在同一变更锁
中确认没有其它引用；批量、全局和受管出口复用均拒绝。运行时解析再次拒绝异常全局引用，避免
回退到直连。迁移 `20261009010000_AddManagedWgcfProfile` 在 SQLite 以原生 DROP COLUMN 回滚；
仅回退到不识别此字段的旧版本时，才需要先将账号迁往可用路由、停止出口并备份数据库与私有目录。

## 统一列表与旧运行器退役（v1.31.82）

代理页将常规代理 DTO 与 `GET /proxies/wgcf` 的档案状态合并为一张表，以
`managedWgcfProfile` / `profile` 关联。同一出口只显示一行；尚未生成代理记录的创建中或
失败档案也必须显示，不能因缺少 `proxyId` 消失。启动、停止、恢复、检测和单账号绑定在
对应表格行内执行；受管出口继续走专用 API，不因合表开放普通编辑、删除或全局共享。

旧 Docker WARP 管理器、后台维护与状态/刷新 API 已移除，不再挂载 Docker Socket 或加载
旧 WARP Compose 覆盖。数据库中历史 `kind=warp` 记录只用于识别和迁移，不再作为可用路由；
账号或全局配置仍引用它时必须在连接前失败，禁止降级直连。不能用普通 SOCKS/HTTP 参数
重新包装旧记录绕过该限制。

`warp_pool` 仅候选已启用、`ready`、监听就绪、检测成功且无账号/全局引用的
`managedWgcfProfile` 出口。选取后取得独占租约，再核对实际状态；每份出口最多绑定一个
账号，已占用或未就绪的候选不能复用，池为空时在首次 Telegram 连接前失败。
受管轻量出口不参与普通代理的定时 HTTP 健康巡检；只有验证 `warp=on` 的专用检测
才能将其标记为可分配，避免普通网页可访问时误报 WARP 已就绪。

升级前逐账号迁移并记录旧路由、新代理 ID、出口检测及只读 Telegram 资料验证结果。
全部受影响账号验证通过后，才移除旧全局引用、旧代理记录及旧容器；不由应用启动自动清理。
回滚至支持轻量运行器的 v1.31.81 时保留迁移后的数据库和 `wgcf-warp` 材料，不能恢复
迁移前数据库而把账号重新指向已删除容器。无需新增数据库迁移。

## 统一创建与首次连接（v1.31.81）

所有新建入口使用 `IManagedWarpProvisioner`，固定 SOCKS5，不再创建官方 WARP Docker 容器。
v1.31.82 已移除旧容器的运行管理与路由使用。登录、导入和逐账号绑定的
`warp_per_account` 必须提供 `acceptWarpTerms=true`；条款未接受或环境不可用时不得连接 Telegram。
Core 通过宿主接口创建，不引用 Web。运行器等待 `ready`、`listening`、检测成功及出口 IP 后
返回代理和独占租约。不可预测的租约 token 只在进程内部传递，不能由公开 DTO 提交。

`TemporaryWarpClaimStore` 阻止其它账号流程和网页启停、恢复抢占首连出口。登录重发验证码、
二维码重生成沿用冻结代理。正式绑定完成后释放租约；激活失败仍保留已绑定出口，账号保持停用。
失败或取消先严格断开客户端，再停止未绑定出口，保留注册材料。队列取消保存停止意图，即使
后台注册稍后完成也要停止。重启仅停止带临时归属且没有正式绑定的档案，保留普通网页出口。

内部请求标识映射为确定性档案名，UUID 只负责幂等，不授予出口归属。首次 HTTP 响应丢失后
不得凭公开 UUID接管其它登录会话；保留已停止材料供核对。暂不提供跨新登录会话的自动接管。
验收包括拒绝未接受条款、未就绪不连 Telegram、租约互斥、取消收尾、重试复用和重启分类清理。

网页启停和恢复须在整个操作期间持有档案占用；获取首连租约后重新读取数据库与运行态，
防止读取旧启用状态后被并发停止。已正式绑定的临时档案允许故障恢复，仍保留原请求归属。
导入清理若严格断开客户端失败，进程内保留租约及档案占用，拒绝其它流程抢用出口。
此时不停止仍可能被客户端使用的出口；需重启面板并核对账号绑定与档案状态后人工恢复。

## 独立工具集成与恢复

凭据 JSON 包含精确 `panelUrl` 和管理员 Cookie，Linux 限制为 0400/0600。拒绝来源重定向，
默认 HTTPS；明文内网需显式选择。每个请求设置 15 秒连接/读超时和总响应期限，最后一次
阻塞读取可能再占用最多 15 秒；响应限制 4 MiB，不保存原始响应。

绑定流程：分页读取账号列表 → 记录旧代理 ID/原全局模式 → 持久化唯一代理名称和创建意图 →
创建 `wireguard_warp/socks5` → 面板出口检测 → CAS 绑定 → 回读账号代理。API 返回 HTTP 200
仍需检查 `success=1/failed=0`，不得仅靠状态码宣布成功。网络超时可能发生在提交之后，
重试通过唯一名称和当前账号绑定恢复；找不到已尝试创建的代理时停止，避免重复资源。
`POST /proxies/{id}/test` 未加载账号导航且 `isGlobal` 为默认值，不能用来判定占用；工具在
提交绑定前及绑定后都用 `GET /proxies` 的完整 DTO 重新检查账号数量和全局用途。

独立工具仍拒绝自动迁移旧受管 WARP 账号；这类迁移由运维在升级前逐账号完成并验收。
新出口已有其它账号或全局用途时拒绝绑定。已有宿主 API 只对 `ExpectedProxyId` 比较，不区分并发从直连到全局
（二者 ID 都为 0）的瞬间切换；运维者应避免同时编辑待迁移账号。跨工具/面板 UI 的并发
一对一占用不是数据库唯一约束，本工具不宣称提供这种保证。

档案保留旧代理引用用于回滚；不自动删除面板代理、WARP 注册或密钥。上游注册失败之后的
清理语义不是事务回滚，缺少材料时必须人工核对，不允许自动循环创建。

## 验证

```bash
timeout 60s python -m unittest discover -s tools/wgcf-warp/tests -v
mkdocs build --strict
```

`.github/workflows/wgcf-tool.yml` 在 Linux 验证注册部分成功、超时、配置注入、端口冲突、
独立密码、敏感输出、子进程启停/重启恢复，以及本地模拟面板的出口失败、绑定失败、丢失
创建响应、人工换绑和重定向。镜像构建校验固定二进制 SHA256，再执行真实 wireproxy
`configtest`，不注册或建立真实 WireGuard 隧道。

云端验收必须额外执行运维文档中的小样本注册和 Telegram 路径；未执行时 PR/Release
明确写“未实网账号绑定验收”，不能据此关闭完整实网功能诉求。v1.31.82 的应用回滚保留
已经迁移的新路由与持久卷；仅跨越受管标识数据库迁移回退时，才按前述迁移回滚合同执行。
