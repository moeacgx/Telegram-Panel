# 常见问题

## 代理页显示“未使用 WARP”，是不是独立 WARP 失效了

不一定。代理页顶部检测的是面板服务自身出口；“未使用 WARP”只表示面板本身没有走
Cloudflare WARP。下方代理列表会单独显示每个 WARP 容器的出口和“WARP 已连接”状态。

## 出口 IP 是一串带冒号的字符，为什么没有城市和运营商

带冒号的地址通常是有效 IPv6。当前检测源稳定提供 IP、国家码和 WARP 状态，不保证返回
城市或运营商；这些字段为空不表示检测失败。详情见
[代理管理与账号出口](../guides/proxy-management.md)。

## WARP 容器还在运行但出口挂了怎么办

受管 WARP 默认会自动巡检。连续两次出口检测失败后，面板会重启原容器、保留数据卷并
重新检测；绑定账号的客户端会重新建立，但不会降级为直连。代理页会显示连续失败次数、
恢复状态、最近与下次巡检时间，也可以手动刷新单个或全部 WARP。

健康 WARP 默认不会每 720 分钟强制重启，以免无故更换 Telegram 账号 IP；确需参考
tokens-pro 的周期刷新时，可设置 `TP_WARP_SCHEDULED_REFRESH_ENABLED=true`。

## 普通代理或 Resin 的出口 IP 为什么一直不变

从 v1.31.44 起，启用的普通 HTTP/SOCKS5 和 Resin 默认每 5 分钟重新检测出口，代理列表
与账号列表会共用更新后的 IP 快照。普通代理只检测、不重启；Resin 使用独立探测身份并在
完成后回收临时 Lease，不会替换账号自身的稳定身份。MTProxy 不能承载 HTTP 出口探测，
因此不参与这项巡检。

若“最近检测”没有更新，先确认 `Proxy__Egress__Maintenance__Enabled` 未设为 `false`，再
查看容器日志中的 `Proxy egress maintenance` 错误，并手动检测单个代理以区分代理不可用
和后台任务未运行。需要回滚时关闭该开关并重建容器；账号绑定和数据库结构不会改变。

## 发送验证码提示“session 被占用/进程占用”

- 确保不要多开多个面板实例共享同一个 `sessions` 目录（会互相锁文件）
- 如果刚修改了全局 `ApiId/ApiHash` 或 API 配置池，建议重启面板再登录；已有账号仍优先使用账号保存的 API 配置，如需切换请重新登录或重新导入该账号

## 数据同步后账号显示 “A task was canceled” 或失效

适用于 v1.31.45 及以上版本。账号数据同步遇到单个 Telegram 请求取消时，只会将该账号记为本轮同步失败并保留原有 Telegram 状态，不会因为一次代理/网络瞬时中断把账号标为 Session 失效。

先在任务中心查看失败详情并重新运行同步任务；如果仍持续失败，再对该账号执行状态刷新，检查代理出口和 Session 错误。只有出现 `AUTH_KEY_UNREGISTERED`、`SESSION_REVOKED` 等明确错误时，才需要重新登录账号。

## 数据同步提示 “Cannot find type for ctor” 怎么办

适用于使用 `WTelegramClient 4.4.8`（Telegram Layer 228）的版本。该错误表示 Telegram 向该
会话返回了相邻旧 Layer 的对象构造器，不是 `Desktop / Windows 10` 等设备画像直接造成的网络故障。
包含此修复的版本会兼容 `user#31774388` 和 `channel#1c32b11c`，无需修改设备画像、降级依赖或删除
Session 文件。

升级并重启后重新运行同步任务；成功判据是频道/群组同步完成，任务详情不再显示上述构造器错误。
若错误中的构造器编号不同，请保留完整编号、发生时间和任务日志反馈。若同时提示
`AUTH_KEY_UNREGISTERED` 或 `SESSION_REVOKED`，那是独立的 Session 问题，应按账号重新登录流程处理。
回滚应用版本不会修改数据库或已有 Session。

## 账号列表为什么显示“连接异常”，定时任务还能自动恢复吗

适用于 v1.31.46 及以上版本。“连接异常”表示最近一次检测遇到代理断开、请求超时或临时 IO
故障；“检测异常”表示创建频道探测或账号资料读取没有得到确定结论。两者都不等同于账号或
Session 失效，也不会进入“只看废号”或被清理。后台会按系统设置中的间隔小批量复查这些账号。

使用动态代理时，账号状态刷新和群聊活跃任务准备阶段会在首次瞬时失败后释放旧客户端，重新读取
账号当前代理并重试一次，因此不再需要通过“切换到同一个代理再应用”清理连接。成功判据是代理
出口轮换后直接刷新状态或运行定时任务仍能恢复。若仍失败，先在代理管理中检测出口并确认代理
认证和有效期，再检查是否存在 `AUTH_KEY_UNREGISTERED`、`SESSION_REVOKED` 等明确 Session 错误。
回滚到 v1.31.45 不需要修改数据库或 Session 文件。

## 侧栏为什么默认不展开子菜单

为避免首次打开页面时侧栏过长，账号、频道、群组、机器人和扩展模块等子菜单默认收起。
点击父菜单即可展开；刷新页面后会再次收起，不影响当前页面高亮和路由访问。

## 使用 HTTP 打开面板时，为什么复制链接会报错

适用于 v1.31.42 及以上版本。面板会优先使用浏览器的 Clipboard API；在 HTTP、权限被
拒绝或浏览器不支持该 API 时，会自动回退到传统复制方式。复制成功的判据是页面显示
“已复制”提示，并能在文本框中粘贴出完整内容。

如果两种复制方式均被浏览器策略禁用，请改用 HTTPS 访问后重试。回滚到旧版本不会影响
已生成的频道或群组链接，但 HTTP 环境可能再次出现 `writeText` 报错。

## 手机上编辑计划任务为什么不会横向溢出

从 v1.31.59 起，任务中心的“编辑计划任务”弹窗会根据视口宽度自动收窄，手机端表单标签改为顶部布局，Cron、状态、任务配置和“保存计划任务”按钮按单列排列。成功判据是弹窗完整显示且无需横向滚动；如果仍看到旧的 760px 固定宽度，先强制刷新页面或重新创建容器以加载最新前端资源。回滚到旧版不会修改计划任务数据，只会恢复旧版布局。

## 任务中心如何配置私信任务

适用于宿主 `v1.31.76`。`direct_message.live` 和 `direct_message.batch` 在任务中心使用
宿主原生表单，创建、普通编辑和普通复制都会在当前页面回填配置；主流程不使用模块
iframe。当前不支持私信 Cron 创建、计划编辑、计划复制或立即执行，已有计划应先停用后改用
普通任务编辑。计划任务、执行中任务和历史任务三张表统一从“操作”下拉菜单进入可用动作。

表单只有在私信模块已安装、启用且任务定义返回 `canCreate=true` 时才显示。读取账号、群组或
图片资产接口失败会禁用保存，不会发出创建或编辑请求。先确认管理员登录状态和模块日志，
必要时暂停相关任务、停用模块并恢复 `LastGoodVersion`；详细 JSON 字段、默认值、边界与接口
列表见[私信任务配置合同](../developer/modules.md#v13176)和[私信任务 API 参考](../reference/api.md#v13176)。

分类下拉框内部使用账号分类 ID，但提交 JSON 的 `senderCategory` 必须是分类名称字符串，
不能填数字或数字字符串；批量字段为 `manualUsernames`，词典显示为“用户名词典”。风控默认值为
`dedupeDays=3`、`dedupeScope=Task`、`cooldownSeconds=60`、`rolling24h=20`，范围分别为
`0..3650`、`Global|Task`、`0..86400` 和 `1..1000`。模块解析或校验失败返回 4xx，表单保持不可提交。
需要不去重时打开表单中的“不去重”开关，系统提交 `dedupeDays=0` 并保留当前去重范围；关闭后会恢复
本次编辑最后使用的正数天数，未设置过时恢复 `3`。冷却秒数和滚动 24 小时上限不会因此关闭。
新建任务默认按“当前任务”去重：上一任务给某用户发送过消息，不会阻止新任务再次发送；只有选择
“本模块全部任务”时才会跨任务拦截。去重记录和判断由私信模块执行，宿主前端仅承载配置。

发送时，某个发送账号受目标或来源限制会自动换用下一个账号；全部发送账号都无法处理该目标，或
目标用户名已失效时，系统只跳过该目标并继续。网络断线等无法确认是否已发送的情况会把该目标标记为
待人工裁决，禁止换号重复发送，但其他目标继续执行。只有整个发送账号池永久不可用时任务才会暂停。

## 群组详情如何直接踢出管理员

当前开发版起，打开“群组详情”后，管理员表的“头衔”右侧会显示非创建者管理员的踢出图标。
确认后系统会按已同步的群组关联选择执行账号，先撤销目标的管理员权限，再以非永久方式将其移出群组；
创建者没有该按钮，也不能被此功能操作。

前提是群组已同步、至少有一个本系统账号仍是管理员且 Telegram Session/代理可用。成功后刷新
管理员列表，目标不再出现。若提示执行账号权限不足，请使用拥有“添加管理员”和“封禁用户”
权限的账号；若提示目标状态已变化，先刷新管理员列表。若看到“已撤销管理员权限，但尚未踢出”，
说明 Telegram 的第二步未完成，应先刷新确认当前状态，不能连续重复点击。

该功能不改数据库结构。若目标属于本系统账号，踢出成功或目标已不在群组时会删除该群组关联；只
完成撤销管理员权限时会保留成员关联并取消创建者、管理员标记。回滚到旧版本只会失去详情页按钮，
已经完成的 Telegram 操作和已同步的关联不会自动恢复；需要恢复时只能由群组创建者或有权限的
管理员在 Telegram 中重新设置管理员，并按需重新同步群组。

## 多个每小时计划任务为什么不再全部整点启动

从 v1.31.70 起，Cron 计划任务会在下次运行时间上加入随机延迟，默认最多 300 秒，避免多个同 Cron 任务在整点同时创建批量任务。成功判据是创建多个 `0 * * * *` 任务后，“下次运行”分散在整点后的几分钟内；如果业务必须精确整点运行，把 `ScheduledTasks__RandomDelaySeconds=0` 写入容器环境或本地配置并重启。回滚不需要迁移数据库，旧版会按保存的 `NextRunAtUtc` 继续跑，下一次重算后恢复旧逻辑。

## 快速点击页面时出现“页面加载失败 cancel”怎么办

这是前端把正常的用户取消或路由取消误判为致命错误。适用修复版本起，`cancel`、`close`、Vue Router 的导航取消和浏览器 `AbortError` 不再触发“页面加载失败”遮罩；真正的 JS 运行时错误和前端 chunk 加载失败仍会显示该提示。成功判据是快速连续点击菜单、按钮或弹窗取消时不会出现 `cancel` 遮罩；若仍出现，先强制刷新页面以加载最新前端资源。回滚到旧版不会影响数据，只会恢复误报行为。

## 批量换绑邮箱为什么只显示失败账号

从 v1.31.62 起，批量换绑邮箱会在同一个弹窗内按账号实时追加失败项，成功账号不再单独列出，也不会在任务结束后再弹一个包含全部账号的结果窗口。弹窗完成摘要仍会显示成功/失败数量；如果出现失败，会保留账号编号、阶段和后端原因，方便复制排查。

如果失败原因提示 `Cloud Mail Token 无效或已失效`，请在 Cloud Mail 管理端重新生成 Token，再到面板「系统设置 → Cloud Mail 对接」保存。成功判据是 Cloud Mail API 返回正常，批量弹窗不再等待 60 秒后才显示失败。

## 服务器出现大量 `[curl] <defunct>` 僵尸进程怎么办

从 v1.31.63 起，Docker Compose 面板服务启用轻量 init 进程，负责回收健康检查和其它外部子进程。长期运行的容器如果此前已经积累僵尸进程，需要先重建面板容器；仅刷新页面不会清理它们。成功判据是 `docker ps` 中面板容器正常运行，`ps` 不再持续增加以 dotnet 为父进程的 `[curl] <defunct>`。

建议同时检查磁盘 IO、容器日志和代理/WARP 数量；封号本身不应直接产生 curl 僵尸进程。如果重建后仍持续增长，请保留 `ps -ef --forest`、容器启动方式和对应时间段日志再反馈。
